# Release Guide

> Read this before releasing, bumping versions, or touching `VERSION` / `package.json` / `CHANGELOG.md`.

## Version Sources of Truth

- `VERSION` and `package.json` `version` are co-sources of truth for the current release version.
- Kept in sync by `scripts/bump-version.sh` — **do not edit either manually**.

## Release Workflow

Run `./scripts/bump-version.sh [major|minor|patch|--auto]` — it orchestrates:

1. `commit-and-tag-version` (bumps `package.json` + `VERSION` together)
2. `git-cliff` (regenerates `CHANGELOG.md` from Conventional Commits)
3. Commits, tags `vX.Y.Z`, and pushes to trigger GitLab CI

`--auto` derives the bump level from Conventional Commits since the last tag.

## Tooling Config

- `.versionrc` — `commit-and-tag-version` config; bumps `package.json` + `VERSION` together, skips its own changelog/commit/tag (the script handles those).
- `cliff.toml` — `git-cliff` config (Conventional Commits → `CHANGELOG.md`).
- `package.json` / `pnpm-lock.yaml` — root dev tooling (git-cliff, commit-and-tag-version); **not a workspace root**.

## CHANGELOG.md

- Auto-generated by `git-cliff` from Conventional Commits.
- **Do not edit by hand** — manual edits will be overwritten on the next release.
- Regenerate manually with `pnpm changelog`.

## Gotchas

- `CHANGELOG.md` is auto-generated — manual edits are overwritten on the next release.
- Releases are orchestrated by `scripts/bump-version.sh`; never bump `VERSION` or `package.json` version by hand.
